# 2026 YW第一课全量考点：独立交付规范

## 1. 成果定位

本成果是主交付之外的独立“全量考点”资料，从考官视角提取 91 个课程资产中一切可能被命题的信息。它不进入主 Word 的 `ASR 结果 / OCR 结果 / GPT 融合校对结果` 三段结构，不改变、不阻塞主交付。

“考点提炼”不等于压缩摘要。允许把叙述改写为便于命题和复习的原子化知识点，但不得以“重要性”判断删除细节。只要一个事实能够形成判断题、单选题、多选题、填空题、排序题、匹配题、情景题或操作题，就应被保留。

## 2. 唯一证据边界

- 唯一内容证据是本轮正式完成的 `evidence_corpus.json` 中逐资产的完整 ASR 与 OCR。
- ASR 正文只接受主流程中由 `mimo-v2.5-asr` 产生并通过源指纹与完整性校验的结果。SenseVoice、Whisper 等本地审计输出不是 ASR，不得进入考点证据或考点正文。
- 不读取、不复用旧 GPT 融合稿，也不以本轮主交付的 GPT 融合正文替代原始 ASR/OCR 证据。
- 调试文件 `evidence_corpus.incomplete.json` 只能用于结构检查，禁止据此撰写正式考点。
- 原始资料缺失、破损外链或无法恢复的附件只形成“证据缺口”，不得推测其中内容。

## 3. 正式开工门禁

只有以下条件全部满足，某资产才可从“门禁等待”转为“提炼中”：

1. 正式 `evidence_corpus.json` 已生成，顶层状态为完整，资产数恰好为 91。
2. 资产的 `asset_id` 和 `source_sha256` 与 `asset_manifest.json` 精确一致。
3. 资产具有唯一、合法的 `evidence_sha256`，且证据内容重新计算后仍匹配。
4. ASR/OCR 完整性门禁通过；无静默缺页、缺帧、缺段或失败项。
5. 若来源存在已知不可恢复缺口，缺口已显式记录并与可用证据隔离。

门禁未满足时，正式考点完成数保持 `0/91`。等待证据不是遗漏，也不以不完整结果抢跑。

## 4. 排序和资产粒度

- 一级顺序严格采用《YW第一课线上课程目录》的 81 条原顺序。
- 同一目录条目下有多个资产时，按主清单的 `catalog_position → catalog_suborder → 2026优先 → 2025其次 → 文件名自然序 → source_sha256` 排列。
- 91 个物理课程资产逐一处理，不能把视频与配套课件合成一个资产，也不能把 2025/2026 同名但 SHA 不同的文件合并。
- 每个考点先绑定单一资产；91/91 完成后才可另做跨资产对比表。跨资产表必须回指所有来源资产，不能覆盖逐资产原始考点。
- 聚合视频或资料必须携带 `coverage_positions`，并按 `docs/exam-points-catalog-coverage.md` 逐一反查其覆盖的每条目录子项，不能只按资产标题提炼一次就默认覆盖完整。

## 5. 必须穷举的命题维度

逐资产阅读时，至少逐项检查以下维度；没有相关内容时才可标记“不适用”：

1. 定义、概念、术语、原理、观点、目标、意义、特征和分类。
2. 数字、日期、年份、次数、比例、金额、时限、阈值、数量、单位、层级、型号和序号。
3. 人名、地名、组织名、制度名、文件名、工程名、系统名、品牌名、产品名和其他专名。
4. 主体、对象、职责、权限、分工、责任边界、审批关系和问责关系。
5. 制度条款、适用范围、触发条件、前置条件、例外、豁免、禁止性要求和后果。
6. 流程、步骤、先后顺序、输入输出、办理路径、检查点、结束条件和回退路径。
7. 风险、隐患、红线、禁令、注意事项、错误做法、事故原因、防控措施和应急要求。
8. 案例人物、时间、地点、背景、行为、关键事实、处置、结果、责任认定、原因和启示。
9. 系统入口、菜单路径、页面、页签、字段、按钮、选项、状态、提示、上传材料和操作结果。
10. 相近概念、易混选项、上下位关系、并列项、相反项、适用场景差异和常见误区。
11. 图表、流程图、时间线、组织图、界面截图以及仅在画面或附件中出现的信息。
12. 教师反复强调、显式提示“注意/必须/不得/首先/只有/除外”等内容，但不得因此忽略未强调的可考细节。

## 6. 直接模型撰写原则

- 正式考点正文由 GPT 逐资产直接理解完整证据后撰写，代码不得自动生成、关键词抽取、模板填词或把 ASR/OCR 机械拼接成考点。
- 代码只可做清单、分批、身份绑定、进度统计、格式组装和只读 QA。
- 超长资产允许分段阅读，但分段笔记只是模型内部中间材料；每个资产必须经过文件级最终通读后才可定稿。
- 一个考点尽量表达一个可独立设问的事实；同一事实的条件、例外、单位和边界必须与主句放在一起，不能因原子化而丢失限定。
- 证据中的重复可在语义完全一致时合并；不同页、不同主体、不同条件或不同阶段的相似表述必须分别保留。
- ASR 与 OCR 冲突时不得擅自二选一。保留可确认部分，并将冲突写入 `evidence_status` 与复核清单。

## 7. 单条考点最低字段

每条考点至少包含：

- `point_id`：资产内连续编号，例如 `A002-KP001`。
- `dimension`：命题维度，可多选。
- `statement`：完整、可检索、可直接作为标准答案依据的考点陈述。
- `question_angles`：可采用的题型和设问角度，不凭空扩展答案。
- `answer_elements`：作答不得遗漏的关键词、数字、条件、步骤或责任主体。
- `traps`：证据支持的易混点、错误选项构造点或边界；没有则为空数组。
- `evidence_refs`：回指 ASR 段或 OCR 页/帧/附件记录；至少一项。
- `evidence_status`：`ASR+OCR互证 / ASR单证 / OCR单证 / 证据冲突待复核` 之一。

每个资产头必须携带 `asset_id`、`source_name`、`source_sha256`、`evidence_sha256`、目录位置和资产顺序。不得仅用文件名绑定，因为存在同名不同版本。

## 8. 质量门槛

单资产完成必须同时满足：

- 身份：四项身份字段有效且与正式证据一致。
- 覆盖：12 个命题维度逐项检查完毕；所有数字、专名、流程词、条件词、否定词和界面控件均完成反查。
- 忠实：每条考点至少有证据定位；不存在证据外推断。
- 完整：无“其他内容略”“等等”“详见原文”等省略性兜底。
- 可检索：专名、数字、字段和制度名称保留原词，不只使用指代词或上位概念。
- 可命题：考点陈述包含必要主语、谓语、条件和结论，脱离上下文仍可理解。
- 复核：对 ASR/OCR 冲突、孤立数字、否定词、时序和单位做二次检查。

全量完成必须达到 `91/91`，并完成跨资产重复/冲突/版本差异核对。任何资产失败不以空白、旧稿或机械抽取兜底。

## 9. 独立交付物

正式交付与主 Word 完全分离：

- 结构化母本：`.work/first-principles-2026/exam-points/exam_points_final.json`
- 独立 Word：`outputs/最终交付/2026年YW第一课全量考点.docx`
- 只读 QA：`.work/first-principles-2026/exam-points/exam_points_qa.json`
- 进度台账：`docs/exam-points-progress.md`

Word 采用 81 条课程目录作简要目录，正文按 91 个资产展开。考点文档不使用主 Word 的红色 GPT 正文约定，避免两份成果在视觉上被误认为同一结构。

## 10. 已知来源限制

目前清单审计已知：`电网员工职业发展机会.pptx` 引用 7 个未随源文件提供的外部附件，`员工基本职业素养系列课程之职业礼仪.pptx` 引用 1 个未提供的外部 PPT，另有课件包含无法解析的 `NULL` 外部图片关系。这些缺口应在对应资产中列为来源限制，只对现有可读取证据提炼考点，不虚构缺失附件内容。
