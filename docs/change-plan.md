# 刷题体验与本地题库改造方案

## 架构边界

沿用 React + TypeScript 页面、Excel 导入器、IndexedDB 本地题库与进度、Capacitor/PWA 离线构建。`data/` 存放原始与转换后的 Excel，整个目录从 Git 排除；经题库提供者确认，标准化后的 7 份题库从 `public/data/` 进入公开构建。作答记录不上传。

## 需求与验收

| 需求 | 实现位置与行为 | 验收标准 |
| --- | --- | --- |
| 逐库导入 | `scripts/convert-banks.mjs` 递归读取 `data/`，每份源 Excel 在 `data/converted/` 生成一份标准 17 列 Excel；文件夹参与题库命名 | 输出文件数等于源文件数，转换结果用生产导入器回读并逐题比较。无法正确作答的源题跳过并报告行号 |
| 错题划分 | 首页根据当前题库显示错题。选“全部题库”时先显示按题库分组的入口；错题列表始终只展示一个题库 | 不同题库错题不混列、不跨库清除 |
| 错题删除 | IndexedDB 将指定题目的 `wrong` 归零，保留作答与收藏；列表支持单题移除、本题库清空 | 关闭重开后仍已清除；批量操作只影响当前题库 |
| 首页精简 | 移除品牌/练习统计顶栏及累计统计方格。设置放在“开始练习”标题旁，操作区只保留错题、收藏和模拟考试 | 手机和桌面宽度均可操作，窄屏可滚动，主要点击区约 44 px 以上 |
| 选择记忆 | 保存题库、题型、难度、数量、顺序、保命题筛选到设备本地 `localStorage` | 重开应用后恢复；题库被删除或题型/难度不再存在时回退到有效选项 |
| 题型与难度 | 列表从当前题库的题目生成，切换题库时校正不适用的选项 | 不显示所选题库没有的题型或难度 |
| 模拟考试 | 用当前题库、题型、难度、数量筛选结果随机组卷；交卷后一次结算 | 显示总题数、答对、答错、跳过和按总题数计算的分数，重复交卷不重复记账 |

## 界面判断

依据 Apple 的 [布局](https://developer.apple.com/design/human-interface-guidelines/layout)、[按钮](https://developer.apple.com/design/human-interface-guidelines/buttons)和[表单浮层](https://developer.apple.com/design/human-interface-guidelines/sheets)建议：将设置按钮贴近练习筛选区域；把主要行动放在筛选下方；错题管理作为有明确范围的浮层；手机端避免固定整屏高度造成内容裁切，并照顾安全区域。保留现有绿色视觉体系，以清晰的层级和留白减少装饰性统计。

## 执行与校验

题库转换、错题数据、考试结算分别独立实现；首页及持久化由主页面整合。运行组件/数据库测试、TypeScript 编译和生产构建；检查 `data/` 与转换产物保持被 Git 忽略。源表有缺失选项或答案歧义时记录具体行号供人工复核，不臆造答案。
