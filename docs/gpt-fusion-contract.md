# GPT 逐文件融合正文契约

## 输入

每次只处理一个物理课程资产，输入包含：

- `asset_id`
- `source_name`
- `source_sha256`
- 完整 `ASR 结果`
- 完整 `OCR 结果`

不得把旧 GPT 融合稿作为输入证据。

## 模型任务

完整阅读 ASR 与 OCR，直接写出该文件可供检索和答题使用的最终课程正文。正文不是摘要，不限定篇幅；应尽可能完整地保留：

- 课程中的定义、概念、观点、原理和背景；
- 全部数字、日期、比例、单位、型号、名称和专有词；
- 全部流程、步骤、菜单、字段、按钮、条件、例外和注意事项；
- 全部制度条款、职责边界、风险点、案例事实、处理结果和经验要求；
- 语音未说出但画面出现的标题、表格、图示、界面和附件信息；
- ASR 与 OCR 能相互校正的专名和错字。

允许模型基于语义合并同一事实的重复出现，但不得因为内容看似次要而删除；不同页面、不同场景或不同条件下的信息必须保留。

证据冲突且无法可靠判断时，采用不夸大的表述，保留可确认信息；不得编造缺失内容。

## 输出

只返回该文件的最终正文段落：

```json
{
  "asset_id": "...",
  "source_sha256": "...",
  "evidence_sha256": "...",
  "task_sha256": "...",
  "model": "如实填写实际完成文件级最终复核的模型标识",
  "paragraphs": ["最终正文第一段", "最终正文第二段"]
}
```

这些标识字段只用于证明正文与本文件、本次证据和本次模型任务一一绑定，不进入 Word。
红色 Word 正文逐字取自 `paragraphs`，也只取自 `paragraphs`。程序不得在前后追加任何内容。

## 禁止事项

- 不写摘要、概览、结论性缩写或“主要讲了”。
- 不写 `ASR结果`、`OCR结果`、`ASR底稿`、`OCR底稿`、`完整语音识别底稿`、`完整的语音识别底稿`、`完整的OCR识别底稿`、`ASR/OCR原文`、`完整画面文字`、`OCR补充`。
- 不写“根据ASR/OCR”“根据识别结果”“从画面可见”“识别结果显示”等处理过程。
- 不写帧号、时间戳、置信度、缓存路径、请求信息或模型日志。
- 不复制整份原始底稿作为兜底。
- 不使用旧融合正文补齐模型失败。

## 文件级最终复核

超长文件可以分段阅读，但最终交付前必须由 GPT 重新看到：文件身份、完整证据索引以及全部分段阅读结果，并输出一次文件级最终 `paragraphs`。程序不能把分段回答直接串接为最终正文。
